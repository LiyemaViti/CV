# 5. Agile Logbook

## Evidence limitation

The uploaded project ZIP does not contain meeting minutes, daily stand-up notes, retrospective notes or a dated Agile logbook. Do not invent historical dates or claim that a meeting occurred if you cannot verify it.

## Logbook template

Create one entry for each real meeting/work session you can remember or substantiate from messages, commits, task-board updates or notes.

| Date | Activity / discussion | My work or contribution | Decision / outcome | Blocker and next action |
|---|---|---|---|---|
| [actual date] | [what happened] | [what I did] | [actual outcome] | [actual blocker/action] |
| [actual date] | [what happened] | [what I did] | [actual outcome] | [actual blocker/action] |
| [actual date] | [what happened] | [what I did] | [actual outcome] | [actual blocker/action] |
| [actual date] | [what happened] | [what I did] | [actual outcome] | [actual blocker/action] |

Possible evidence sources, if available:
- GitHub commit dates and messages
- Pull requests or issues
- Trello activity/history
- Meeting notes or class planning documents
- Screenshots or messages that document decisions

## Source-based technical note

The README says the frontend can be run from the `frontend` directory using `npm install` and `npm run dev`, and that it uses mock data until the backend exists. The event service has `USE_MOCK = true`. If you personally tested these instructions, record the date and actual result as a new current logbook entry; do not backdate it.
